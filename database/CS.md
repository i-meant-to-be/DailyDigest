# CS

- 오버라이드 vs. 오버로딩
  - 오버라이드 | 상위 인터페이스 혹은 클래스에서 `open` 등으로 상속 가능하다고 명시해놓은 함수의 구현을 하위 클래스에서 덮어쓰는 것
    → 동적 다형성 (runtime dynamic polymorphism)
  - 오버로딩 | 같은 이름을 가지면서 서명은 다른 함수 여럿을 만들 수 있게 하는 것
    → 정적 다형성 (compile-time static polymorphism)
- 프로세스와 스레드의 차이
  둘 다 단말에서 동작하는 하나의 프로그램을 나타내긴 는데, 크게 보면 프로세스는 실행에 필요한 자원을 소유하며, 스레드는 프로그램의 스케줄링 및 실행을 담당함.
  - 프로세스는 모든 스레드가 공유하는 코드, 전역 변수 등 정보를 가진다는 점에서 자원 소유 및 관리라는 특성을 주로 보임
  - 스레드는 실제로 코드를 실행하며 그 과정에서 문맥 전환을 거치며 스케줄링에 기여한다는 점에서 스케줄링/실행의 특성을 주로 보임
  또한 하나의 프로세스에 다수의 스레드가 붙을 수 있는 1:N 구조를 가진다는 점에서도 둘은 엄연히 다름
- 프로세스 스위칭과 스레드 스위칭의 차이
  - 일단 문맥 교환이 프로그램 실행에 있어 중요한 이유는 현대 CPU는 고성능 코어 여러 개를 사용하기 때문에 문맥 관리가 매우 자주 일어나기 때문. 따라서 효율적인 실행을 위해서는 문맥 관리를 줄여야 함.
  - 이를 위해서는 무거운 프로세스 스위칭보다는 가벼운 스레드 스위칭이 더 유리함.
  - 먼저, 메모리는 보통 연속적으로 할당되어 있지 않은데, 이는 메모리 관리가 보통 페이지라고 불리는 가상 주소에 의해 이루어지기 때문임. 이는 파편화를 방지하기 위한 대책.
  - 그리고 논리 가상 주소를 실제 물리 프레임과 연결해주는 페이지 테이블이 메모리 안에 존재.
  - 보통 메모리 접근 속도 향상을 위해 페이지 테이블 중 최근에 접근된 엔트리는 CPU의 MMU(Memory Management Unit) 안에 있는 TLB(Translation Lookaside Buffer) 캐시에 저장해 둠.
  - 스레드 간 교환이 일어날 때에는, 프로세스에 속한 전역 변수 등 데이터와 코드는 바뀌지 않기 때문에, TLB의 변화도 비교적 적음.
  - 그러나 프로세스 간 교환이 일어날 때에는, 러프하게 말해서 모든 데이터가 바뀌기 때문에, TLB도 완전히 비워지게 됨.
  - 따라서 비워진 이후 당분간은 RAM에서 페이지 테이블을 참조해야 하고, 이로 인해 지연이 발생함.
- 병렬성(parallelism)과 동시성(concurrency)의 차이점
  - 병렬성은 실제로 여러 코어가 물리적으로 병렬 작업하는 것
  - 동시성은 논리적으로 보기에 같은 시간에 여러 작업이 동시에 처리되는 것처럼 보이도록 하는 것
  - 동시성은 충족되나 병렬성은 충족되지 않을 수 있음. 만약 개발자가 실수로 코어 1개에 작업을 할당하거나 실제로 코어가 1개밖에 없다면!

- 클린 아키텍처의 정의와 중요한 이유?
  도메인 로직과 기술 로직을 분리하는 것을 말함.
  - 도메인 로직은 그저 데이터가 필요할 뿐 그 데이터가 어디서 어떻게 생산되는 지에 관해서는 알아야 할 필요가 없고 그래서도 안 됨.
  - 마찬가지로 기술 로직은 데이터를 생산하고 보관, 가공하는 일만 잘 하면 되지 그 데이터가 어디서 어떻게 사용하는 지에 대해서는 알 필요가 없고 그래서는 안 됨.
  - 이렇게 도메인 로직과 기술 로직을 분리할 경우, 데이터 소스가 바뀌어도 인터페이스 등을 활용해서 손쉽게 교체가 가능해짐.
  - 따라서 유지보수성과 유연성의 확보가 가능.
