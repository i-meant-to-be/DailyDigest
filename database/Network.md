# Network

- TCP와 UDP, 그리고 이들의 차이는?
  둘 다 4계층에 해당하며 소켓 통신의 방법들. 다만 신뢰성과 연결 방식에서 차이점이 있다:
  - TCP
    - 소켓의 신뢰성 있는 전송을 목표로 하며, 재전송 및 오류 복구 정책 등을 다수 채택하기 때문에 신뢰성은 높으나 성능이 느림
    - 한 번 소켓을 열면 닫기 전까지는 계속 열려 있음
  - UDP
    - 신뢰성을 아예 고려하지 않기 때문에 TCP에서 채택하는 각종 옵션이 전혀 없어 속도는 빠르지만 오류 복구는 온전히 개발자의 몫
    - 연결을 수립하지 않고 그냥 던지기만 하는 비연결형
- TCP 3단 악수에 대한 설명
  - 단말 A에서 연결 의사 표명 (SYN)
  - 단말 B에서 연결 의사에 대해 수락(ACK)하며 자신도 연결 의사 표명 (SYN)
  - 단말 A는 B의 ACK를 받고 연결 수립
- TCP가 UDP 기반 QUIC으로 대체되는 이유
  - 일단 성능이 나쁘다
  - TCP 프로토콜이 제정된 지가 꽤 지났기 때문에, 현대의 기술적 상황과 맞지 않는 일부 옵션들이 포함되어 있기 때문
  - TCP는 데이터 순서를 엄격히 보장하기 때문에 하나가 유실되면 지연이 꽤 큰데, QUIC은 독립적인 스트림을 사용하여 이 문제를 해결한다
  - 모바일에서는 Wi-Fi에서 LTE로 넘어가면 IP가 바뀌고 TCP는 IP가 바뀌면 연결이 끊기지만, QUIC은 IP 대신 별도의 Conn ID를 사용하기에 연결이 끊기지 않음
