## [OS-001] (기초) 프로세스와 스레드의 차이는 무엇인가요?

프로세스는 **실행 중인 프로그램**이며 실행에 필요한 자원을 소유하는 단위임. 스레드는 **프로세스 안의 실행 흐름**으로, 실제 명령을 실행하는 단위임.

- 같은 프로세스의 스레드는 주소 공간과 자원을 공유함. 코드·전역 데이터·힙·열린 파일 등이 공유 대상임.
- 각 스레드는 자기 호출 스택과 프로그램 카운터, 레지스터 문맥을 가짐. 같은 코드를 실행하더라도 각자 실행 위치와 호출 상태를 유지함.
- 따라서 한 스레드가 공유 힙이나 전역 데이터를 변경하면 다른 스레드도 그 변경을 볼 수 있음. 동시에 접근하는 가변 데이터에는 적절한 동기화가 필요함.
- 프로세스 제어 블록(PCB)은 커널이 프로세스 식별자·상태·자원 정보 등을 관리하는 자료구조임. 구체적인 자료구조와 스레드 실행 문맥을 저장하는 방식은 운영체제 구현에 따라 다름.

하나의 프로세스에는 하나 이상의 스레드가 있을 수 있음. 자원을 소유하는 프로세스와 그 자원 안에서 실행하는 스레드를 구분해야 함.

참고: [프로세스와 스레드](https://learn.microsoft.com/en-us/windows/win32/procthread/about-processes-and-threads), [Linux 커널의 태스크 관리](https://rust.docs.kernel.org/kernel/task/struct.Task.html)

## [OS-002] (심화) 프로세스 스위칭과 스레드 스위칭은 왜 비용이 다른가요?

- 문맥 교환이 자주 일어나는 이유는 실행 가능한 스레드 수가 코어 수보다 훨씬 많아 시분할해야 하기 때문. 여기에 입출력 대기로 인한 자발적 양보가 더해짐. (코어가 많아서가 아니라 오히려 코어가 모자라서 생기는 일)
- 따라서 효율적인 실행을 위해서는 무거운 프로세스 스위칭보다 가벼운 스레드 스위칭이 유리함
- 먼저, 메모리는 보통 연속적으로 할당되어 있지 않은데, 이는 메모리 관리가 페이지라고 불리는 단위의 가상 주소로 이루어지기 때문임. 파편화를 방지하기 위한 대책
- 그리고 논리 가상 주소를 실제 물리 프레임과 연결해주는 페이지 테이블이 메모리 안에 존재
- 보통 메모리 접근 속도 향상을 위해 페이지 테이블 중 최근에 접근된 엔트리는 CPU의 MMU(Memory Management Unit) 안에 있는 TLB(Translation Lookaside Buffer) 캐시에 저장해 둠
- 스레드 간 교환이 일어날 때에는 같은 프로세스에 속한 데이터와 코드가 그대로이므로 주소 공간이 바뀌지 않고, 따라서 TLB를 무효화할 필요가 없음
- 프로세스 간 교환에서는 주소 공간이 통째로 바뀌므로 원리상 TLB 무효화가 필요함. 다만 현대 x86-64와 ARM은 PCID·ASID로 TLB 항목마다 주소 공간 꼬리표를 달아 전체 비우기를 피함
- 그럼에도 캐시 지역성이 깨지고 커널 자료구조를 더 많이 갈아끼워야 해서 프로세스 전환이 여전히 더 비쌈

## [OS-003] (기초) 병렬성과 동시성의 차이는 무엇인가요?

- 병렬성은 실제로 여러 코어가 물리적으로 병렬 작업하는 것
- 동시성은 논리적으로 보기에 같은 시간에 여러 작업이 동시에 처리되는 것처럼 보이도록 하는 것
- 동시성은 충족되나 병렬성은 충족되지 않을 수 있음. 개발자가 실수로 코어 1개에 작업을 할당하거나 실제로 코어가 1개밖에 없다면
