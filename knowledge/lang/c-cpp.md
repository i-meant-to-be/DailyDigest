# C / C++

## [CPP-001] (실무) `NULL`과 `nullptr`의 차이점은 무엇인가요?

- `NULL`은 C에서 널 포인터 상수를 나타내는 매크로이며 구현에 따라 `0` 또는 `(void*)0`으로 정의됨
- `nullptr`은 C++11에서 도입된 포인터 리터럴이며 `std::nullptr_t` 타입을 가짐. 아무것도 가리키지 않음을 타입 수준에서 표현
- C++에서는 `void*`가 다른 포인터 타입으로 암묵 변환되지 않기 때문에 `NULL`을 `(void*)0`으로 둘 수 없고, 그래서 대개 정수 `0`(또는 `0L`)으로 정의됨
- 그 결과 `f(int)`와 `f(char*)` 오버로드가 있을 때 `f(NULL)`이 `f(int)`를 호출하는 모호성 문제가 생김. `nullptr`는 바로 이 문제를 없애려고 도입된 것이므로, `NULL`이 `nullptr`로 자동 변환되는 것이 아니라 **`nullptr`가 `NULL`의 결함을 대체하는 관계**로 이해해야 함

## [CPP-002] (실무) C/C++에서 모든 포인터 접근마다 Null을 확인하는 것은 적절한가요?

그렇지 않다.

- 모든 포인터 접근마다 Null을 확인하는 것은 오버엔지니어링
- 대신, 외부에서 데이터가 들어오는 지점에서만 검사하고 그 이후에는 문제가 없을 것이라고 간주
  → 이를 신뢰 경계(trust boundary)라고 부름
- 개발 시에는 `<cassert>` 헤더의 `assert` 함수를 사용해서 혹시 모를 문제를 잡아내면 됨
  (`assert` 함수는 배포 빌드 시에는 코드에 포함되지 않음)

## [CPP-003] (기초) 참조자란 무엇인가요?

`&` 연산자로 설정 가능하며, `&`을 붙여 준 변수의 또 다른 이름(alias)으로 간주됨

- 반드시 실제 존재하는 객체에 붙여줘야 함
- 위 특성 때문에 절대로 `nullptr` 값을 가질 수 없음
- 재할당 불가능

## [CPP-004] (기초) 참조자와 포인터의 차이는 무엇인가요?

- 재할당
  - 포인터는 재할당 가능
  - 참조자는 재할당 불가능
- Nullable 여부
  - 포인터는 Nullable
  - 참조자는 Non-nullable

## [CPP-005] (실무) 참조자와 포인터 중 무엇을 쓸지 결정하는 기준은 무엇인가요?

"가능하면 참조자 사용, 포인터는 꼭 필요한 상황에서만 사용"

- '아무것도 없음'이라는 상태를 논리적으로 표현해야 할 때 (`nullptr`을 사용해야 할 경우)
- 실행 시간에 지시 대상을 바꿔야 할 때 (e.g., 연결 리스트)
- `new`와 `delete`로 메모리 소유권을 직접 관리해야 할 때

## [CPP-006] (기초) `auto`는 무엇인가요?

`auto`는 컴파일 시간에 정해지는 유동적인 자료형으로, 컴파일러가 초기화 식을 보고 자료형을 판단하여 결정. 컴파일 시간 이후에는 절대로 변경 불가능.

## [CPP-007] (실무) C++ 람다 함수는 어떻게 작성하나요?

```cpp
int num = 3;

auto lambda = [num](int input) -> int {
    return input * num;
};
```

- `[]` 안에는 외부 범위에서 가져와야 할 변수를 정의. Capture라고 부름
- `(T input) -> R`의 형태로 입력과 출력을 정의
- 출력 타입은 생략해도 됨 (컴파일러가 `return` 문을 보고 알아서 출력 타입을 추론)
- 람다는 식이므로 변수에 대입할 때 마지막에 세미콜론이 필요
