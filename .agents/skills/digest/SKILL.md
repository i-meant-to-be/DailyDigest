# 다이제스트

이 저장소의 지식 문항을 골라 질문지를 만들고, 사용자가 적은 답을 채점하고, 문항별 이해 상태를 갱신한다.

## 역할 분담 — 먼저 읽을 것

**계산은 `scripts/digest.mjs`가 하고, 판단은 네가 한다.**

| 스크립트가 하는 일 | 네가 하는 일 |
| --- | --- |
| 문항 선정, 상태 전이, 감쇠, 집계, 세션 관리 | 문제 문장 작성, 채점, 왜 틀렸는지 설명 |

지켜야 할 것:

- **`state/mastery.json`과 `state/sessions.json`을 직접 열거나 편집하지 마라.** 187문항이 들어 있고 앞으로 더 늘어난다. 스크립트 명령으로만 다뤄라.
- **미채점 세션을 찾겠다고 `sessions/`를 훑지 마라.** `pending` 명령이 인덱스 한 줄만 읽고 알려 준다.
- 출제할 때는 `select`가 준 6문항의 메타와, **그 문항들의 원문만** 읽어라.

## 모드 판별

인자가 없으면 먼저 이걸 실행한다.

```
node scripts/digest.mjs pending
```

- `"pending": "2026-09-02-1430"` 같은 값이 나오면 → **채점 모드**
- `"pending": null`이면 → **출제 모드**
- 결과에 `others`가 있으면 미채점 세션이 여럿이라는 뜻이다. 임의로 고르지 말고 목록을 보여 준 뒤 사용자가 고르게 하라.

명시 호출:

| 입력 | 동작 |
| --- | --- |
| `/digest new [문항수] [--subject cs/network]` | 출제 모드 강제 |
| `/digest grade [세션id]` | 채점 모드 강제 |
| `/digest status` | 리포트 갱신 후 요약 출력 |

## 출제 모드

### 1. 상태를 맞추고 문항을 고른다

```
node scripts/digest.mjs sync
node scripts/digest.mjs select
```

`--n 8`로 문항 수를, `--subject cs/network`로 과목을 좁힐 수 있다.

`select`의 출력은 이런 모양이다.

```json
{
  "picks": [
    { "id": "NET-002", "subject": "cs/network", "difficulty": "기초",
      "slot": "wrong", "source": "wrong", "reason": "이전 오답",
      "last_asked": "2026-08-30", "gaps": ["마지막 ACK 단계 누락"] },
    { "id": null, "topic": "TLS 핸드셰이크", "subject": "cs/network",
      "difficulty": null, "slot": "gap", "reason": "주제 대장 공백" }
  ],
  "notes": ["..."]
}
```

`notes`는 정책을 그대로 적용하지 못한 사정이다. 반드시 질문지나 안내 메시지에 옮겨라. 사용자가 "왜 오답이 안 나왔지?"를 궁금해하지 않게 하는 장치다.

### 2. 문제를 쓴다

`id`가 있는 문항은 해당 지식 파일에서 그 문항의 원문을 읽고, **제목을 그대로 쓰지 말고 면접에서 나올 법한 문장으로 다듬어라.** 원문 제목이 이미 질문 형태면 그대로 써도 된다.

`slot`이 `gap`인 문항은 `id`가 없다. `topic`만 보고 **네가 새로 문제를 만든다.** 난이도도 네가 정한다. 이때 `PROFILE.md`의 눈높이를 참고하라.

이전 지적(`gaps`)이 있으면 같은 지점을 다시 짚는 문제로 만들어라. 똑같은 문장을 반복하는 것보다 낫다.

### 3. 세션을 열고 질문지를 쓴다

```
node scripts/digest.mjs open --ids NET-002,CMP-001,AND-022,...
```

`gap` 문항은 아직 ID가 없으니 `--ids`에 넣지 않는다. 이 명령이 세션 디렉터리를 만들고, 출제한 문항에 `last_asked`를 찍고, 인덱스에 등록한다. 출력의 `quiz` 경로에 아래 형식으로 파일을 쓴다.

```markdown
# 다이제스트 2026-09-02 14:30

<!-- digest: id=2026-09-02-1430 -->

각 문항의 `### 내 답변` 아래에 답을 적고, 다 적으면 `/digest`를 다시 실행하세요.
참고 자료를 보지 말고, 면접장에서 말할 수 있는 만큼만 적으세요.

---

## 1. [NET-002] TCP 3단 악수를 설명해 주세요

`cs/network` · 기초 · 이전 오답(2026-08-30) · 지난 지적: 마지막 ACK 단계 누락

### 내 답변


---

## 2. [신규] TLS 핸드셰이크는 어떤 순서로 이루어지나요

`cs/network` · 실무 · 주제 대장 공백 — 지식 파일에 아직 없는 주제

### 내 답변

```

머리글의 대괄호 안에는 ID를, `gap` 문항은 `[신규]`를 쓴다. 그 아래 한 줄에 과목·난이도·**출제 사유**를 적는다. 출제 사유는 정책이 실제로 어떻게 적용됐는지 사용자가 검증하는 수단이므로 빠뜨리지 마라.

### 4. 경로를 알려 준다

질문지 경로를 알려 주고, 답을 적은 뒤 `/digest`를 다시 실행하면 된다고 안내한다. 문제 내용을 대화창에 다시 늘어놓지 마라.

## 채점 모드

### 1. 답변을 읽는다

`pending`이 알려 준 경로의 `quiz.md`를 읽고 각 `### 내 답변` 블록을 꺼낸다.

**비어 있으면 0점이 아니라 미응답이다.** `score`를 `null`로 두면 스크립트가 상태를 건드리지 않는다. 답을 안 쓴 문항 때문에 오답 목록이 오염되면 안 된다.

### 2. 채점한다

`id`가 있는 문항은 지식 파일의 원문과 대조한다. 원문이 `> (미작성)`이거나 `[신규]` 문항이면 표준 정답을 기준으로 한다.

채점 기준은 `references/grading.md`에 있다. **반드시 읽어라.** 특히 이 사용자에게는 후하게 주지 않는 것이 핵심이다.

### 3. 결과를 쓴다

세션 디렉터리에 `result.md`를 쓴다. 형식과 반드시 담아야 할 것은 `references/grading.md`에 있다.

### 4. 상태를 갱신한다

채점 결과를 JSON 파일로 쓰고 스크립트에 넘긴다.

```
node scripts/digest.mjs update --session 2026-09-02-1430 --file <채점결과.json>
node scripts/digest.mjs report
```

채점 결과 JSON은 `update`에 전달하기 위한 **임시 파일**이다. `update`와 `report`가 모두 성공한 것을 확인한 뒤 삭제하고, `.graded` 세션 디렉터리에 남기지 않는다. 둘 중 하나라도 실패하면 원인 확인과 재시도를 위해 삭제하지 않는다.

채점 결과 파일의 형식:

```json
[
  { "id": "NET-002", "score": 2, "gaps": ["마지막 ACK 단계를 언급하지 못함"] },
  { "id": "CMP-001", "score": 4, "gaps": [] },
  { "id": "AND-022", "score": null }
]
```

`gaps`는 다음 출제 때 같은 지점을 겨냥하는 근거이자, 사용자가 자기 약점의 성격을 파악하는 자료다. "몰라서 틀림"과 "알지만 설명하지 못함"을 구분해서 적어라.

### 5. gap 문항을 등록한다

`[신규]` 문항은 아직 지식 파일에 없다. 채점이 끝나면:

1. 해당 과목 파일에 새 ID로 문항을 추가한다. ID 규칙은 `knowledge/README.md`에 있다.
2. 본문은 **사용자 답변을 다듬은 것**을 넣는다. 다만 답이 부실했다면(2점 이하) `> (미작성)`으로 남겨 다음에 다시 나오게 한다.
3. `knowledge/SYLLABUS.md`의 해당 줄 끝에 `— <새 ID>`를 붙이고 `[ ]`를 `[x]`로 바꾼다.
4. `node scripts/digest.mjs sync`를 실행해 상태 기록에 등록한다.
5. 그 다음에 그 ID의 점수를 `update`로 반영한다.

### 6. 원문 갱신 제안

사용자 답이 원문보다 정확하거나, 채점하다 원문의 오류가 드러났다면 **조용히 고치지 마라.** `docs/AUDIT.md`에 항목을 추가하고 채점 결과 말미에 "원문 갱신 제안"으로 알린 뒤 승인을 받아라. 지식 원문은 사용자의 것이다.

## 완료 처리

**출제만 마친 시점에는 커밋하지 않는다.** 질문지와 상태 파일 변경은 작업 트리에 그대로 두고 사용자가 답을 적기를 기다린다.

채점까지 마쳐 필요한 파일 갱신과 검증이 끝나면 `AGENTS.md`의 **다이제스트 결과 게시** 규칙에 따라 출제와 채점에서 생긴 변경을 **하나의 커밋으로 묶어** 푸시한다. 원격 푸시까지 성공해야 그 세션이 완료된 것이다.
