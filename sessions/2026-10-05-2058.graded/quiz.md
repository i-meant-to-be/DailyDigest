## 1. [AND-032] Android 앱에 Baseline Profile을 적용하면 실행 성능이 개선되는 원리는 무엇인가요? 주요 사용자 흐름을 기준으로 준비하는 과정과 효과를 검증하는 방법도 설명해 주세요.

`platform/android` · 실무 · 이전 오답 · 지난 지적: 목적과 사전 컴파일 원리, 생성·검증 방법을 설명하지 못함

### 내 답변

Baseline Profile은 JIT가 아닌 AOT(Ahead of Time) 컴파일러로 실행될 부분을 개발자가 직접 정의하는 작업을 의미.

Android 앱은 JIT 컴파일러와 AOT 컴파일러가 함께 컴파일함. JIT 컴파일러는 코드를 필요한 즉시 컴파일하기에 앱 패키지에 바이너리가 생략되어 크기가 줄어든다는 장점이 있지만 대신 런타임에 컴파일을 하는 만큼 성능 하락이나 지연이 있을 수 있음. 반면 AOT 컴파일러는 미리 바이너리로 컴파일 후 앱 패키지에 포함하므로 런타임 성능은 개선되지만 앱 설치 시간이 오래 걸리는 단점이 있음.

핵심 기능 등 사용자가 자주 사용하거나 시작 지점 등 UX에 큰 영향을 주는 부분을 Baseline Profile로 지정하면 이 부분은 AOT 컴파일러로 컴파일되어 JIT 컴파일러 특유의 런타임 오버헤드를 동반하지 않게 됨. 따라서 사용자가 가장 많이 사용하거나 통계적으로 활동이 많은 기능을 Baseline Profile에 등록하고, 설치 시간 및 기능 실행까지 필요한 시간을 측정 및 프로파일링하여 향후 Baseline Profile 적용 여부를 재검토할 수 있음.

## 3. [CMP-018] Compose가 화면을 만드는 Composition, Layout, Drawing 단계는 각각 무엇을 결정하나요? 화면 상태가 바뀔 때 세 단계를 항상 전부 다시 실행해야 하는지도 설명해 주세요.

`platform/compose` · 실무 · 답을 적어 둔 적 없는 문항

### 내 답변

Composition 단계는 화면에 무엇이 들어가고 무엇이 들어가지 않을지를 결정하는, 즉 무엇을 정할지 결정하는 단계. Layout 단계는 그리기로 결정이 된 UI의 실제 크기를 실측하는 단계. Drawing 단계는 Layout 단계에서 결정된 실질적인 픽셀 데이터를 하드웨어 API로 그려내는 단계.

화면 상태가 바뀐다고 세 단계를 항상 전부 다시 실행해야 하는 건 아님. Compose는 상태(`State`) 값 변화 여부에 따라 재구성을 건너뛸지 여부를 결정할 수 있어서, 건너뛰기가 결정되면 Layout 단계와 Drawing 단계는 실질적으로 필요하지 않게 됨. 오직 변화가 발생한 부분에 대해서만 작업이 진행됨.

## 5. [DSG-001] 오버라이드와 오버로딩은 어떻게 다른가요? 각각의 예를 들고, 호출할 구현이 결정되는 시점도 비교해 주세요.

`cs/design` · 기초 · 답은 정리했지만 아직 점검받지 않은 문항

### 내 답변

오버라이드는 상위 클래스의 함수를 하위 클래스에서 덮어쓰는 것을 의미하고, 오버로딩은 매개변수들의 조합을 다르게 하여 같은 이름을 가진 함수를 여러 개 선언하는 것을 의미.

오버라이드의 예시는 다음과 같음: 군사 보호 구역에 접근하는 메소드 `enterArmyBase`를 가지는 `Person` 클래스를 상속하는 `Soldier` 클래스가 있다고 가정. 이 때 상위 클래스 `Person`에서는 입장을 거부하는 동작으로 구현되어 있다고 해도, 하위 클래스 `Soldier`에서 입장을 허락하는 구현으로 오버라이드 가능.

오버로딩의 예시는 다음과 같음: 정수와 비정수 자료형 간 연산. `integer.add`라는 하나의 함수에 대해 매개변수를 `interger.add(a: Int)`, `integer.add(a: Float)` 등으로 선언해두면 두 번째 연산자로 정수가 들어오든 실수가 들어오든 정상적인 계산이 가능.

호출 구현이 결정되는 시점은 오버라이드의 경우 실행 시간임. `var person: Person`이라는 변수에 대해서 `person.enterArmyBase`가 호출된다고 할 때, `person`의 인스턴스가 `Person`일지 `Soldier`일지는 컴파일 시간에 결정할 수 없기 때문.

오버로딩은 컴파일 타임임. 같은 이름의 함수라고 해도 매개변수(서명)로 구분이 가능하기 때문.

## 6. [OS-001] 프로세스와 스레드는 자원 소유와 실행 관점에서 어떻게 다른가요? 같은 프로세스의 스레드들이 공유하는 자원과 개별적으로 갖는 자원을 구분하고, PCB를 누가 관리하는지도 설명해 주세요.

`cs/os` · 기초 · 숙지 상태 재점검 슬롯을 이전에 불완전하게 답한 문항으로 채움(2026-09-18) · 지난 지적: 코드·전역 데이터 공유 범위를 같은 프로세스의 스레드 사이로 한정하지 못함; PCB를 커널이 관리하는 자료구조로 설명하지 못함

### 내 답변

프로세스는 자원 소유 단위, 스레드는 스케줄링의 단위. 프로세스는 실행하지 않으며, 스레드가 실질적으로 작업을 실행함.

프로세스에는 코드, 전역 및 정적 변수 등 전체 스레드에서 공유하는 자원을 소유하며, 각 스레드는 프로세스의 공유 자원을 바탕으로 하여 자신의 영역 내에서 호출 스택, 스레드 지역 스택(thread-local stack)을 관리함으로써 실질적인 작업을 수행.

PCB는 Process Control Block의 준말로 프로세스 ID 등 프로세스 관리에 필요한 데이터를 가지고 있는 자료구조임. PCB는 운영체제, 즉 커널이 관리하며 프로세스가 가지는 코드 등 공유 데이터와는 별개의 것.
